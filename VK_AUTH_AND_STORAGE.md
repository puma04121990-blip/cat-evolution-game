# VK Bridge: авторизация и облачное сохранение

## Подтверждённые методы

| Задача | Метод | Практическое применение |
|---|---|---|
| Инициализация | `VKWebAppInit` | Вызывается один раз при старте игры. |
| Профиль игрока | `VKWebAppGetUserInfo` | Получает данные текущего пользователя без дополнительных прав; достаточно для отображения имени и статуса входа. |
| Облачное чтение | `VKWebAppStorageGet` | Читает строковые значения по массиву ключей. |
| Облачная запись | `VKWebAppStorageSet` | Сохраняет пару ключ–строка в VK Storage; данные привязаны к `user_id`, а не устройству. |
| Токен API | `VKWebAppGetAuthToken` | Не нужен для хранения через VK Storage; оставляется только для будущих социальных API, чтобы не запрашивать лишние права. |

## Ограничения и резервный режим

VK Storage поддерживается во ВКонтакте на Android, iOS, Mobile Web и Web. Значение одного ключа ограничено 4096 символами, а для сериализованной строки документация указывает безопасный предел 2236 символов. Реализация должна хранить компактный снимок игры под одним ключом `tiny_skyline_save_v2`, ограничивать отправку частотой и использовать `localStorage` как локальный fallback вне VK или при ошибке Bridge.

`VKWebAppStorageSet` допускает не более 1000 операций в час на пользователя. Поэтому игра пишет облачный снимок не чаще одного раза в несколько секунд и только после значимого изменения или фонового автосохранения. При запуске более свежий облачный снимок заменяет локальный; при сбое обе версии не удаляются.

## Источники

1. [VKWebAppStorageGet](https://dev.vk.com/bridge/VKWebAppStorageGet) — ключи, ответ `keys`, поддержка Android/iOS/Mobile Web/Web.
2. [VKWebAppStorageSet](https://dev.vk.com/bridge/VKWebAppStorageSet) — бессрочное хранение, привязка к `user_id`, лимиты и длина значения.
3. [VKWebAppGetUserInfo](https://dev.vk.com/bridge/VKWebAppGetUserInfo) — профиль текущего игрока без дополнительных прав.
4. [VKWebAppGetAuthToken](https://dev.vk.com/bridge/VKWebAppGetAuthToken) — токен требует ID приложения, настроенного URL и явного набора прав.

## Проверка реализации

В обычном браузере игра корректно остаётся в режиме «Локальный профиль», создаёт и обновляет `localStorage`, а аудиоконтекст запускается только после пользовательского клика. Контролируемый мок VK Bridge подтвердил последовательность `VKWebAppInit` → `VKWebAppGetUserInfo` → `VKWebAppStorageGet` и отложенную запись `VKWebAppStorageSet` с ключом `tiny_skyline_save_v2`.

Отдельно проверен приоритет более нового облачного снимка: полученное состояние заменило локальное, сумма энергии обновилась в интерфейсе, а статус отобразил «синхронизировано». Это не заменяет обязательную проверку в реальном тестовом приложении VK, но подтверждает логику выбора и резервный сценарий в браузере.

Контрольные снимки в размерах 375×812 и 812×375 подтвердили, что профиль и статус синхронизации не перекрывают главные действия. В узком портрете остаётся компактный значок VK, а метаданные профиля скрываются; в альбомной ориентации показываются имя и статус, при этом город, контракт и основные настройки остаются видимыми одновременно.
